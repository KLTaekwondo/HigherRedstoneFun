# HigherRedStoneFun

> 一个面向 **Minecraft 26.3 / Paper** 的科技插件，v0.1。
> 玩法灵感来自粘液科技（Slimefun），但在能源网络、机器架构与农业育种三个方面做了针对性重构。

---

## 这是什么

三个模块，一条完整的科技线：

| 模块 | 内容 | 门槛 |
| --- | --- | --- |
| **基础机器** | 增强工作台、研磨机、压制机、冶炼炉、离心机、锯木机 | 无（靠固体燃料） |
| **高级电力机器** | 燃煤 / 太阳能 / 地热 / 核反应堆发电，电容储能，电力熔炉、电力研磨、组装机、分子重组机 | 需要基础机器产出的零件 |
| **基因工程** | 采样、测序、拼接、注入、培育舱；8 种作物 + 6 种动物 | 需要电力机器的精密件 |

**v0.1 规模**：88 个自定义物品、24 台机器、95 条配方、14 种配方类型、4 个基因位。

---

## 快速开始

### 1. 构建

```bash
gradlew build
```

产物：`build/libs/HigherRedStoneFun-0.1.0.jar`

> 需要 **JDK 25**（Paper 26.3 是 Java 25 目标）。若你的 JDK 装在其他位置，可在 `gradle.properties` 中修改
> `org.gradle.java.installations.paths`。

### 2. 安装

把 jar 放进服务端 `plugins/` 目录，重启服务器。

启动日志会打印内容统计与恢复的机器数量：

```
[HigherRedStoneFun] ========================================
[HigherRedStoneFun]  HigherRedStoneFun v0.1.0 已启用
[HigherRedStoneFun]  物品: 88 | 机器: 24 | 配方: 95
[HigherRedStoneFun]  已恢复机器: 0 台
[HigherRedStoneFun]  启动耗时: 795 ms
[HigherRedStoneFun] ========================================
```

### 3. 上手

```
/hrf guide      # 打开图鉴，浏览全部机器与配方
/hrf genetics   # 查看基因工程玩法说明
```

用 `/hrf give <物品ID>` 拿到第一台**增强工作台**，放下它，右键打开，开始合成。

## 玩法要点

### 基础机器

所有基础机器烧固体燃料（煤、木炭、木板、岩浆桶……），不需要电。

**从原版工作台开始**：先在普通工作台里做出**机器框架**（4 铁 + 4 铜 + 1 铁块）
和**铜导线**（1 铜锭 → 3 根），再用它们搭出**增强工作台**——这是科技树的起点。

| 机器 | 作用 |
| --- | --- |
| 研磨机 | **1 粗矿 → 2 粉**（矿石翻倍，基础层核心收益） |
| 压制机 | 锭 → 板 → 齿轮 / 导线 |
| 冶炼炉 | 比原版熔炉快 4 倍 |
| 离心机 | **1 粉 → 1 锭**（无损），副产物是真正收益 |
| 锯木机 | 1 原木 → 6 木板 |

> **产线核心**：`1 粗铁 → 研磨 → 2 铁粉 → 离心 → 2 铁锭 + 副产物`。
> 相比直接用熔炉（1 粗铁 → 1 铁锭），**产能翻倍**——这就是造机器的理由。

### 电力

**导线**：铜块、避雷针、末地烛（可在 `config.yml` 里改）。
把发电机、电容、用电机器**摆在一起或用导线连起来**就自动组成电网——不需要能源调节器，也不限制数量。

```
[燃煤发电机]──[电容]──[电力冶炼炉]
              │
         [电力研磨机]
```

**发电机对比**：

| 发电机 | 产能 | 特点 |
| --- | --- | --- |
| 燃煤发电机 | 8 J/t | 最便宜，需要燃料 |
| 太阳能发电机 | 12 J/t | 免费，但必须露天、看天气与昼夜 |
| 地热发电机 | 20 J/t | 需要下方 3 格内有岩浆 |
| 核反应堆 | 400 J/t | **最强，但会熔毁** |

**核反应堆是唯一有风险的机器**：需要持续投入燃料棒（下界合金碎片等）与冷却剂（蓝冰等）。
一旦冷却耗尽，堆芯开始升温，约 10 秒后**熔毁爆炸**并摧毁机器与内部物品。

查看电网状态：

```
/hrf energy
```

### 基因工程

这是本项目相对原版生态的**核心新增玩法**，把真实的育种循环做进了游戏。

```
① 采集            ② 测序              ③ 拼接（核心）        ④ 注入           ⑤ 收获
手持空样本瓶       样本 + 基因引物      两个基因组 + 拼接酶    空白模板 + 基因组   种下去 / 孵化
潜行右键成熟作物   放进基因测序仪       放进基因拼接机        放进基因注入器
或动物             ↓                   ↓                    ↓
                 基因组(4 个基因位)    逐位取优 + 概率突变    改良种子 / 胚胎
```

**四个基因位**（各 0–5 级）：

| 基因 | 效果 | 满级 |
| --- | --- | --- |
| **生长** | 作物成熟更快 | 约 3 倍速 |
| **产量** | 收获更多 | 约 3.5 倍量 |
| **抗逆** | 抵抗踩踏 | 完全免疫 |
| **活力** | 自动补种 | 100% 自留种 |

**为什么拼接是核心**：每个基因位**独立取两个基因组的较优值**，并有概率突变 +1。
所以你可以把「A 的高生长」和「B 的高产量」定向组合到同一株作物上——
这是**育种**，不是抽卡。反复拼接即可逼近全满级的完美基因组。

**动物基因可遗传**：两只带基因的动物繁殖时，子代每个基因位随机继承父母之一，并有小概率突变。
多代选育就能得到一整个高产畜群。这是原版生态完全没有的体验。

**空样本瓶** = 3 个玻璃，在原版工作台或增强工作台合成。

| `/hrf reload` | 重载配置 | `hrf.command.reload` |

### `/hrf selftest` —— 排障利器

服主可以在服务器里直接运行自检，它会验证 10 组核心机制（共 78 项断言）：

```
▶ 物品身份 (PDC 标记)
▶ 配方匹配与消耗
▶ 能源网络
▶ 基因工程
▶ 作物与动物映射
▶ 机器生命周期 (加工 / 掉落)
▶ 机器存档 (序列化往返)
▶ 工作台安全性 (防复制)      ← 回归测试
▶ 科技树入口                 ← 回归测试
▶ 经济闭环 (防负收益)         ← 回归测试
```

它能明确区分「插件坏了」和「玩家没接电线」，输出形如：

```
  ✔ 发电机产出的电被送入电容 电容电量 0 -> 320 J
  ✔ 机器能完成一次加工 耗时 62 次 tick 调用
  ✔ 自定义物品身份挺过存档 ID=hrf_iron_plate, 数量=7
  ✔ 研磨支持矿石翻倍 (1 粗矿 -> 2 粉) 已支持 ✓
  ✔ 拆机器不会白送产物（复制漏洞已封堵） 回收 hrf_grinder x0 (必须为 0)
  ✘ 网络能发现全部 3 台机器 发现 1 台
```

也可以在启动时自动运行：加 JVM 参数 `-Dhrf.selftest=true`，
或设置 `config.yml` 中的 `debug.run-selftest-on-start: true`。

## 配置

`plugins/HigherRedStoneFun/config.yml`：

```yaml
performance:
  enable-energy-net: true          # 能源网络调度
  enable-machines: true            # 机器调度
  autosave-interval-ticks: 6000    # 自动保存间隔（5 分钟）

genetics:
  wild-crops-have-genes: true      # 野生作物是否携带随机基因
  wild-gene-quality: 0.35          # 野生基因质量
  enable-growth-chamber: true      # 是否允许全自动培育舱
  inheritable-animals: true        # 动物基因是否可遗传

energy:
  cable-materials:                 # 导线方块，可自由更换
    - COPPER_BLOCK
    - LIGHTNING_ROD
    - END_ROD

safety:
  owner-only-machines: true        # 只有主人能打开/拆除机器
  reactor-meltdown-griefing: true  # 反应堆熔毁是否破坏地形
```

## 运维说明

**存档位置**：`plugins/HigherRedStoneFun/machines/<世界名>.yml`，按区块分节。
物品栏用 NBT 字节序列化 + Base64（而不是 YAML 物品序列化），保证自定义标记不丢失。

**区块行为**：机器只在所在区块加载时工作（与原版一致）。区块卸载时会自动保存并暂停，
玩家回来时自动恢复，**不需要重启服务器**。

**性能**：机器按区块分桶调度，开销只与「已加载且含机器的区块数」相关，
与存档里的机器总数无关。导线不是网络节点，摆多少都不影响性能。

## 已知限制（v0.1）

诚实记录没做的事：

- **没有物流系统**：物品需要手动搬运，没有管道/货运。
- **配方硬编码**：`Recipes.java` 里写死，还不能用 YAML 扩展。
- **单文件存档**：每个世界一个 YAML，机器极多时会变大（v0.2 改为按区块分文件）。
- **没有附属 API**：第三方还不能注册自己的机器。
- **基因位只有 4 个**：还没有显隐性（等位基因）模型。
